# Companion (iPhone, iPad, Fold)

Distilled from `design/companion/` (Claude Design, 2026-10-31). Boards: `C-Audit`, `C-Language`, `C-Components`, `C-Handoff`; screens `C-Macs`, `C-Workspace`, `C-Permission`, `C-Question`, `C-Inbox`, `C-MacInfo` (dark, `*-Light`), `C-iPad`, `C-Fold`; Mac colours `C-MacColour`, with the Mac side in `Mac-Settings-Remote` and `Agents-Mate-1280`. The Mac principles in `design-language.md` carry over; this file lists what is different on the phone.

## Colour

System surfaces and label levels (no Mate cream). Accent is Mate green: `#A6D85B` dark, `#357A27` light (white text passes 4.5:1). Accent = the one primary action, selection, unread dot. Success = teal (`#4FB3A0` / `#1F7F70`), diff additions only; done is muted grey. Warning amber = needs you (permission, question). Danger red = failed, stuck, Reject. Surfaces: background `systemBackground`/`systemGroupedBackground` (a plugin section screen, every SDUI slot under More, sits on `systemGroupedBackground`, set once in `SectionScreen`, so surface-1 groups and cards keep an edge in light), surface-1 `#1C1C1E`/`#FFFFFF` (groups, cards, glass base), surface-2 `#2C2C2E`/`#E9E9EE` (user bubble, plain buttons, chips). Accent and tones are the same values as the Mac's Mate theme; the palette does not follow the paired Mac.

### Mac colours (C5)

With two or more Macs paired each Mac has a colour, a name tag and never a role. Tokens `sky blue indigo purple magenta graphite` (dark `#5AC8FA #3D8BFF #8582FF #BF7AF0 #F06FC8 #A1A1A6`, light `#0A78A8 #1F62D0 #5450D6 #8540BF #B02E8C #636369`); the Mac sends the token, an unknown one renders graphite. Shown only next to the Mac's name: the tinted Mac glyph in section headers (Macs, iPad/Fold sidebar), a dot before the Mac name in a row's second line ("Needs you", under titles: workspace, Inbox, session header). Never on buttons, status glyphs, selection, the unread dot, row backgrounds or text. With one Mac: no dots, no tint, no Mac-name prefix. Notification titles lead with the Mac name. Offline Macs keep their colour. The colour belongs to the Mac: chosen on the phone in Mac details (disabled offline, "Connect to change") or on the Mac in Settings → Remote, which also has the title-bar dot (on by default, shown while 2+ Macs are paired to a device).

## Metrics

- Touch: 44pt minimum hit area; capsule buttons 50pt (primary) / 44pt (secondary); ≥ 10pt between opposite choices.
- Type: Dynamic Type (Large Title 34, Title 3 20, Body 17, Subheadline 15, Footnote 13, Caption 12); SF Mono at body − 3 for commands, paths, code.
- Density: a row is a title (≤ 2 lines) plus one state line; no previews. List rows take 11pt vertical insets (`listRowDensity()`): two-line rows ~65pt, one-line ~50pt, Mac colour rows 48pt; the whole cell is the hit area (≥ 44pt).
- Disclosure: a navigable list row (Needs you, workspace, Inbox, session, backlog task) ends in a tertiary › (`RowChevron`) in the compact stack only; iPad / Fold columns show the selection instead: a dim accent tint (`Color.selectedRow`, accent ≈ 20% over surface-1) behind the row, label ink kept, the row's glyph in accent — never a solid accent fill (warning counts on it were unreadable).
- Space and radius: 16pt margins, 22pt above a section; list groups radius 22, cards 20, code 16.
- Navigation: NavigationSplitView everywhere; header = back · title · one ••• menu; the header only navigates.
- Reach: everything that answers lives in the bottom 40% (docked request card + composer).
- Gestures: swipe only for harmless actions (mark read); never swipe to allow, reject or stop.
- Keys on iPad / Fold hardware keyboards: ⌥1 ⌥2 ⌥3 answer, ⌘⏎ send.
- Width breakpoints, not devices: compact < 600pt one stack; regular 600–1000pt two columns (sessions · session; Macs in a toolbar menu); wide > 1000pt three columns (Macs · sessions · session). Folding keeps the open session. A request arriving for another session shows as a banner pinned under the session header that pushes the transcript down (never over it, never a modal): neutral surface-1 card with an outline amber glyph (the filled amber glyph is for this session's own request), title, then "● ‹Mac› · ‹workspace› · wants to run …" (Mac part with 2+ Macs), "N more ›"; no dismiss, it leaves when the request is answered. A subagent session shows "Started by · ‹parent›" above its transcript, linking to the parent.

## Components

- **Session row**: 28pt status glyph, filled amber only when it needs you; title ≤ 2 lines; one state line that says what it wants ("Wants to run go test ./…", "Asks: …", "Running · 4 min", "Stopped · error", "Done · 1 h"); no pills, no ids; subagents nested under the parent, 24pt in per level with no separator between parent and child, labelled "Subagent"; a subagent that needs you (or has one below it) is never folded, the rest fold behind a trailing "N ›" toggle on the parent counting the hidden ones (a parent with a waiting subagent says "N subagents waiting"); the whole row is the hit area; Closed collapsed by default.
- **Status words** everywhere (rows, headers, notifications): Waiting for you · Asking you · Running · Stopped · Done · Closed. Header: state first, toned only when it needs you ("Asking you · ● Mac Studio · subagent", Mac part only with 2+ Macs). A failed session uses the Mac's words from `failure` in `agents.sessions`: row "exit 1" (or "Stopped") in danger ink, header "Stopped · exit 1" / "Stopped · error", the error sentence in danger ink under the transcript, and under it the Mac's way out from `failure.actions`: a glass button per action the Mac lets the phone run ("Retry", "Hand off to a new session", which opens the new session), and an action that only works on the Mac as a secondary line with a Mac glyph ("Sign in on Mac Studio"), never a button; an offline Mac disables the buttons and puts its "Can't answer — … is offline" reason under them (the composer then drops its copy of it). The boards show no recovery on the phone; this follows the Mac. iPad / Fold: the session header is the large inline title on the left with the subtitle under it, and adds the mode from `modeLabel` ("Waiting for you · ● Mac Studio · shop · Ask before edits").
- **Transcript**: user = right bubble on surface-2 (not the accent); agent = flat markdown, code in a surface-1 mono block with horizontal scroll under a row with its language (caption, secondary) and a Copy button (44pt, a check for 1.5 s after a tap, as on the Mac); thought = one collapsed caption row with duration; plan = one card headed "Plan · N of M" (N done, as on the Mac), done = check + muted (no strikethrough), current = accent + semibold, next = secondary; while steps remain, done steps fold behind a "Show done" toggle in the header (a finished plan lists every step); on iPad / Fold with ≥ 520pt of transcript width the plan and the tool group right after it sit side by side; a prose plan followed by a plan entry folds into the card; tool group = consecutive calls in one row, tap to expand (iPad / Fold: a card naming its first three calls, "Show all N", a doc as an "Open <file>" link); a running subagent card shows a spinner and "Running · 1 min", its Stop is in the card's context menu and asks first (never a full-width button); failures stay folded (danger title and border, output on tap; the boards' "failures expand themselves" is overruled, `docs/agents.md` § Transcript folding); diff = three lines inline, "Full diff" opens a sheet. Content is inset below the glass header with a short edge fade.
- **Permission request**: docked above the composer while pending, then one muted transcript row ("Allowed once · go test ./... · 09:42"). Row 1: Allow once (filled accent, full width, 50pt). Row 2: Always allow… (plain) and Reject (plain, danger ink), 10pt apart. iPad / Fold: the command sits inline after the title when it fits on one line, and the answers are one row when they fit — Allow once · Always allow… on the left, the reject options pushed right. "Always allow…" opens a sheet with the rule it will store (e.g. `Bash(go test:*)`) and its scope; the confirm button is plain, Cancel is bold. reject_always is in the card's ••• ("Reject and don't ask again"), never a fourth button. The exact command in mono, the reason in one caption line. Title, command, caption, option labels and order, the ••• options and the rule and scope come from the permission entry's `card` in `agents.transcript` (`docs/agents.md` § Permission card); the phone builds them itself only for a Mac that sends no `card`. Running rows say what the session does from `activity` ("Editing reserve.go · 4 min"); every "Needs you" list is ordered by `needsYouSince`, oldest first.
- **Question**: docks like a permission (amber border), "Claude is asking", the question in Title 3, "Paused until you answer."; the composer placeholder becomes "Answer Claude…".
- **Composer**: [attach (photo glyph)] [field] [send]. The right slot is always Send / Queue (disabled when empty), never Stop. While running: placeholder "Queue a message", caption "Sends after the current turn · Stop is in •••" (iPad / Fold: "Sends after the current turn"). Stop lives in ••• (iPad / Fold: a ■ header button left of •••, not in •••) and asks once. Attachments as 56pt removable thumbnails above the field. An image on the clipboard pastes as an attachment through the keyboard's paste suggestion or the field's Paste menu; there is no Paste button of our own. iPad / Fold: Send shows only once there is something to send (the board's empty composer has none).
- **Macs screen**: a "Needs you" section on top across all Macs listing the actual requests; per-workspace rows say "2 waiting"; offline Macs dimmed with "offline since 18:20"; a Mac lists its workspaces and Inbox only — workspace-scoped plugins (Agents, Backlog) open from the workspace row and switch with a segmented control under its title. iPad / Fold middle column: inline large title (the workspace), no Mac line and no segmented control — Agents / Backlog / Docs and the workspace switch from the folder menu in its toolbar; the session list is plain (no cards, no separators) with the selected row a rounded accent tint (accent 20%). iPad / Fold Macs column: one "Needs you N" row (amber ! glyph, amber count) that opens the full list in the middle column; workspace rows one line with the waiting count right in amber (nothing when none), Inbox with its unread count; Mac headers inline "Mac Studio · online" ("· offline" when "offline since …" doesn't fit).
- **Backlog**: inset grouped sections like Agents, name left and count right, Not now and Done folded ("Not now · 1 ›"); row = 28pt status glyph in a circle (in progress accent play), title ≤ 2 lines led by the priority glyph (`!!` high, none normal, `↓` low) in secondary ink, then "#n · owner or note"; no coloured priority badges.
- **Inbox**: groups Waiting for you / Earlier; unread dot only on unseen actionable items; rows = kind glyph · title · time / body / workspace · session; permission rows show the command; done in muted grey.
- **Empty / offline**: empty states teach in one sentence and give one action ("No Macs yet — Open Clubmate on your Mac, then Settings › Remote › Pair a device." + Scan pairing code). Offline Mac: data dims, "as of 18:20", answer buttons disabled with the reason; never act on a stale request. Its waiting items stay in "Needs you", dimmed with a neutral glyph, under "‹Mac› is offline — answer when it's back."; the request banner skips them.
- **Mac-only nodes** (`graph`, `flow`, `lanes`, `runstrip`): one Footnote line in tertiary ink, an untinted Mac glyph and "Drawn on the Mac", no box; a flow of only ghost cards draws nothing. Unknown node types keep the dashed "<type> isn't supported on the phone · Update Clubmate on this phone" box.

## Data the companion needs (from the `remote` plugin)

Pending summary per session in the list payload (kind permission | question, short text, created-at); pending items across workspaces for "Needs you"; an explicit asking marker with the question text; the exact allow_always rule and scope; last-seen per Mac and a still-pending check before answering; a resolved event when a request is answered elsewhere.
