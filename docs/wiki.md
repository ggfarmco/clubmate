# Wiki

The **Wiki** section is a per-project knowledge base: how subsystems work, why things were decided, examples and guides. Agents write most of it, for the user; the user reads it and edits now and then. Agents also keep a shadow wiki of their own notes (traps, recipes) under `.agents/`, folded in the sidebar under **Agent notes** until opened.

## Storage

- Root: `$CLUBMATE_WIKI_DIR`, else `~/.clubmate/wiki`; the same folder for release and dev builds. Tests set `CLUBMATE_WIKI_DIR` (or `HOME`) to a temp dir; `scripts/test-app.sh` points it at the instance's `wiki/`.
- One folder per project, `<root>/<project>/`, its own git repo. `<project>` is the folder name of the repo's main checkout (`<name>-2`, `-3`, … when the name is taken). `<project>/.wiki.json` holds `{origin, checkout}` (owned by `plugins/internal/wikiroot`): a folder maps to a wiki by its `origin` URL first (normalised: no scheme, user, `.git` or trailing `/`; `git@host:path` = `host/path`; any case), then by its main-checkout path, so every worktree of a repo shares one wiki and a moved checkout keeps it. A folder that is not in a git repo gets a wiki keyed by its path the same way. The home workspace has none (`no wiki here`).
- Pages: `.md`, `.markdown`, `.mmd`, `.html`, `.htm` (`pkg/docext`), at most 4 MiB, no front matter; folders group them. A page path is relative to the project folder; `..`, absolute paths, a `.git` component, and a path that leaves the folder through a symlink are `bad page path`; another extension is `not a page`. Files are written and read through `os.Root`, git runs with literal pathspecs.
- Page metadata in `<project>/.pages.json` (owned by the plugin): per page `title` (first `#` heading, an `.html` page's `<title>`, else the file name), `sources` (repo paths the page explains), `blobs` (the git blob of each source in the writer's worktree at write time, `""` when missing), `writtenAt`, `by` (the agent session's title, else its id, or `you`).
- Single writer: every write and commit holds `<project>/.git/wiki.lock` (exclusive `flock`), project creation holds `<root>/.lock`, so the release and the dev core can write the same wiki. Each write commits at once: author `<by> <wiki@clubmate.local>`, message `<page>: <summary>` (`<page>: deleted`). Edits made outside the plugin (the user in an editor) are committed by a sweep under the same lock, one commit per page, as `you` with `<page>: edited` (or `deleted`): before every read, list and search, and from the section's 3 s poll.
- Links: relative Markdown links between pages; a link to code is its absolute path in the repo's main checkout. The docs viewer's scope includes the workspace's wikis (see [docs-viewer.md](docs-viewer.md) § Scope).

## Stale

Decided in the plugin and sent as `stale`; clients only draw it. A page is stale when, for any of its sources, the default branch's blob (`refs/heads/<default>`, else `origin/<default>`) differs from the recorded one **and** the default branch's last commit touching that path is newer than `writtenAt`. Agents write pages from a worktree before landing, so: before the branch lands main's last touch is older (not stale); after a squash the blob is the same (not stale); a later change on main makes it stale; a deleted source is stale. A page without `sources`, or a wiki of a non-git folder, is never stale. A user edit sets `writtenAt` to the sweep's time and keeps the sources and blobs.

## Commands

| id | args | result |
|---|---|---|
| `wiki.search` (agent) | `query`, `shadow?`, `limit?` (default 20, max 100) | `{hits: [{page, title, snippet}]}`: every word must match (any case); title 3 > heading 2 > body 1 per word, ties by path; `snippet` the first matching body line, 160 runes; an `.html` page matches on its visible text |
| `wiki.list` (agent) | `shadow?` | `{pages: [{page, title, updated, by, stale}]}` by path |
| `wiki.read` (agent) | `page` | `{page, title, content, sources, updated, by, stale, path}` |
| `wiki.write` (agent) | `page`, `content`, `summary`, `sources?` (strings; absolute paths inside the worktree are made relative) | `{page, path}`; creates the project wiki on the first write |
| `wiki.delete` (agent, destructive) | `page` | `{}` |
| `wiki.history` (hidden, not agent) | `page` | `{changes: [{at, by, summary}]}`, newest first, at most 50 |

The project of a command is the calling agent session's worktree, else the workspace's first git folder's selected worktree, else its first folder. Reads never create a wiki (no wiki yet → empty list, `not found`). Errors: `no wiki here`, `bad page path`, `not a page`, `too large`, `not found`. Every write and delete (and a sweep from the poll) publishes `wiki.changed {workspace, page}`.

## Section

- Sidebar: a head row "Wiki · N pages" (shadow pages not counted) with + (New page); a live **Search wiki** field (`textField` `search`, action `search`; while it holds text the tree holds only the hits, best first, as two section labels **Pages** (`sec:hits`) then **Agent notes** (`sec:notes`, searched even while folded), each with its count, a hit's detail being its snippet from the first match on, with a leading … when cut (no highlight); none: "No match for “query”"; opening a hit wraps every match on the page in `<mark>`, gives the first an id `wiki-match-<n>` and sends it as the document's `anchor`, so the page scrolls to it, until the query is cleared or a page is opened another way; Markdown pages only, in the body and never the margin column, never inside mermaid, script or style); **New to you** (`sec:new`, above the tree, hidden when empty): up to 5 pages someone other than `you` changed since you last opened them, newest first, as `mirrorOf` rows `new:<project>/<page>` with an accent dot and "<who> · <time>" (time today, else the date), agent notes left out; a page counts as opened when you select it, follow a link to it, or it is the page shown while Wiki is the selected section; a page you never opened is new only if it changed after the plugin first saw the workspace, so a fresh install lists nothing. The last-opened times live in plugin storage under `read/<workspace>` (`{since, opened: {"<project>/<page>": updated}}`, the page's `updated` at the time, entries of gone pages dropped on the next write, the key deleted with the workspace); while New to you shows, the root pages sit under a **Pages** label (`sec:pages`); every section label folds (in memory); **Pages** (`tree` `pages`, ids `<project>/<page>`): pages at the wiki's root first, then folders as rows `dir:<project>/<folder>` that fold (no icon; a folded one shows its page count; at the top level they draw as section labels), and last the agents' `.agents/` notes as an **Agent notes** row `dir:<project>/.agents`, folded until opened (per workspace in memory) or until one of its notes is the selected page; a workspace with several projects gets one top-level row per project, `project:<name>`; a stale page has a warning `stale` badge.
- Main: the selected page, else the newest one. A `header` with the page's title, its icon, `updated 15:04 by <who>` (the time only for today, `Jan 2 15:04` before, `Jan 2, 2006 15:04` in another year) and the `stale` badge, then **Edit** (primary, E: `editor.open {path, focus: true}` in the workspace's editor), **History** (⌘Y: swaps the page for the list of its changes; Back to page, ⌘Y again, returns), and "…" with Copy path, Reveal in Finder (`open -R` on the page file) and Delete (confirmed: "Delete <page>? It stays in the wiki's git history."). The page body starts on the header's inset, prose keeps an 88ch measure, and a Markdown page's leading `# H1` is not drawn when it matches the title the header shows (an empty `<a>` keeps its anchor, so a link to it still scrolls to the top). The page is a `document` (`pkg/docrender`; an `.html` page as `kind: artifact`); a link to another page of the workspace's wikis selects it, any other doc opens in the docs viewer, a file in the editor; a link outside the workspace's folders and wikis is `not in workspace`.
- Margin column (Markdown pages, not `.html` or `.mmd`): the plugin puts `<aside class="wiki-margin">` and a `<details class="wiki-fold">` with the same sections before the page body (`plugins/wiki/margin.go`; every page-derived string is HTML-escaped, hrefs are percent-encoded). Sections, each left out when empty, no column when all are: **On this page** (the body's h1–h3 after the title is dropped, as `#<id>` anchors; only with ≥ 2; in the column it scrolls past half the window's height), **Stale** (the changed source with the newest commit on the default branch, "`<path>` [and n more paths] changed today 11:02, after this page"), **Changes** (the last 3 from the wiki's git log, summary and time today / date before; "All n changes ⌘Y" when there are more), **Linked from** (Markdown pages of the same project whose Markdown links, outside code, resolve to this page; agent notes last with a lock; parsed links are cached per file by size and mtime). The stylesheet (`document.css`, wiki only through those classes) shows the aside from a 960 px wide page view as a fixed 200 px column flush right with a 40 px gap (`--margin-col`, `--margin-gap`; the body's right padding makes room, `--measure` keeps 88ch), and below 960 only the fold: one row "On this page · 4 changes · stale · 2 links" above the body. A link `clubmate-doc:<page path>#wiki:history` (the fragment has a `:`, which no heading id has) selects that page and opens its History; "All n changes" uses it (mac-ui `TestWikiMarginAllChangesOpensHistory` clicks it). The document's `rev` is the checksum of the whole HTML, so a new backlink or stale state redraws the page.
- A `ui.event` with `agent: true` on New page, Edit, Reveal in Finder or Delete is refused (`not for agents`): agents use the `wiki.*` commands, where `wiki.delete` asks the user.
- Empty wiki: a centred `empty` "No wiki pages yet" — "Agents write here as they work: how things work, why they were decided, examples. You can add a page too." — with **New page**, which writes `untitled.md` (`untitled-2.md`, …) with `# Untitled` and opens it in the editor. The home workspace reads "Open a project workspace to see its wiki."
- While a workspace shows the section, a 3 s poll stats each wiki; a change runs the sweep and re-renders, and every tick re-renders the section so `stale` follows main.
- Keys: E edits the page, ⌘Y shows its history and again goes back (`docs/shortcuts.md`); the phone shows no wiki yet.

## Agent guidance

The tool descriptions and the Clubmate MCP instructions tell agents: search the wiki before exploring a subsystem; after a feature or a decision, update its topic page (how it works, why) with `sources` instead of adding a page per session; traps, recipes and private notes go under `.agents/`; an example that must run is one self-contained `.html` page (same rules as `docs_open`); never write secrets (nothing enforces it).
