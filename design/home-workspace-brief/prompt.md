Clubmate · Home workspace, round 1. Hi. This is a new question for this canvas: how Home, a personal workspace that is always there, looks and behaves on the Mac, the iPhone and the iPad. Page `today` has real screenshots of today's screens (board `Today`, each shot named); page `language` has the language boards (`Principles`, `Patterns`, `Components`, `Tokens`, `C-Language`, `C-Components`, `C-Workspace`). Draw on top of them.

1. What Home is. The user wants one place in Clubmate for life outside a project: talk with an agent about personal plans, keep personal tasks and notes, run things on a schedule. The user's rule: Home is not a different kind of workspace. It does all that a project workspace does (Agents, Backlog, Wiki, Code, Cron, Triggers, worktrees) in its own folder `~/.clubmate/home`, a git repo the core makes. One extra: its agents may read the other workspaces (backlog, sessions, wiki), so a talk in Home sees the whole picture ("what waits for me today in all projects"). They never change another workspace. Home is named "Home" (today it is "~"), the core makes it at start, it is always first in every workspace list, and it cannot be removed (it can be renamed).

2. Today (screenshots on `Today`). Mac: the workspace switcher ⌃⌘W (`mac-switcher`) is a grid of 240×150 tiles, one per workspace open in this window, plus an "Open folder…" tile; × or ⌫ closes a workspace from the window (it stays in Open Recent). The Welcome screen (`mac-welcome`) shows in a window with no workspace: "Clubmate", Open folder… ⌘O, New terminal ⇧⌘N, then Recent (name, folders, "open" when open in a window, a trash on hover). File › Open Recent (drawn as text on `Today`) lists up to 10 workspaces, then Clear Menu. Today Home is hidden from Open Recent and Welcome; ⇧⌘N "New Home Terminal" opens it with a terminal in `$HOME`. iPhone and iPad (`iphone-workspace-menu`, `ipad-workspace-menu`): the workspace capsule "● shop ⌄" on every tab root opens a system menu, one section per Mac (Mac name · state), its workspaces with "n waiting", then Mac Details, and Pair a Mac last (rules in `design/features/device-ux`: the capsule replaced the Macs screen).

3. Questions for you.
(1) The look of Home on the Mac (switcher, Open Recent, Welcome) and on the iPhone and iPad (capsule menu): row or tile, icon, and how "always there, first, cannot be removed" shows. The name is "Home", not "~".
(2) One behaviour choice the user gave to you. Pick one and say why. (a) Home is always first in Open Recent and Welcome, outside the 10-item cap, and Clear Recents does not remove it. In a window's switcher it is first when it is open in that window; you can close it from a window as any workspace. The window model does not change (cost S). (b) Home is always open in every Mac window as its first tile and cannot be closed from a window. This changes the window model: auto-open in every window, restore, Close Workspace refused for Home (cost M/L).
(3) The empty Home on first open: what a new user sees in Agents, Backlog and Wiki of Home. Today these show "Agents aren't available in the home workspace" and "Open a project workspace to see its wiki."; both go away. A project's empty states today: Agents sidebar "No agent sessions", main "Start an agent session with + New"; Backlog "Nothing in the backlog" + "Tasks are ideas and todos, for you or for an agent. …"; Wiki "No wiki pages yet" + "Agents write here as they work: …". Should Home say more (for example what a Home agent can see, a first suggested prompt), or stay the same as a project? Give the exact texts.

4. Constraints. Keep the design language (`Principles`, `Patterns`, `Components`; colour roles, not hex; the Mac font is the terminal font, monospaced; compact, keyboard first; sentence case in the switcher, Welcome and palette; app menus keep Title Case). The phone capsule is a system `Menu` (rows are a label, an SF Symbol and one subtitle line; no custom drawing inside). Empty states are the `empty` node: icon, title, one text, one action button. No new SDUI node. The core list order stays "most recently opened"; each client puts the workspace with `home: true` first. Never a badge for "pinned" alone: badges are only for attention.
