Clubmate · onboarding · round 1

1 · Editor, or none

Pick: A · no editor until you need one. No editor is the default answer, not a setting you have to find. The app starts as agents only; the first time you want to read a change, Clubmate shows it read-only in Agents and offers Neovim once, at the moment it would help.

A · No editor until you need one · pick

First run asks nothing and turns no editor on. No Code in the rail. The first Review changes or Full diff opens a read-only review in Agents, with a one-time offer to turn on Neovim. The question is asked when its answer is used.

B · Neovim, silently

Neovim on by default, nothing asked; "No editor" lives in Settings. Reviews with comments work on day one, but agent-only users carry a Code section they never open, and have to find out how to remove it.

C · Ask on Welcome

A three-way row on Welcome: Neovim · VS Code · No editor. Honest and explicit, but it is a question before any value, the thing r1 removed.

What changes against r1

  • r1 asked the editor on the first open of Code. With no editor there is no Code to open, so the question moves to the first review, where an editor actually earns its place.
  • New installs: both editor plugins off. Existing installs keep what they have.
  • Turning Neovim on adds Code to the rail and reopens the current review in diffview. Nothing else changes; agents never needed an editor.
  • nvim import only exists with Neovim: as the check in "Turn on Neovim?", then as the Neovim config row in Settings, then in the palette. With no editor it is nowhere.
  • Read-only review keeps the keys of a list: j/k next file, o fold, ⌘⏎ ask for changes, ⎋ back to the session. Asking for changes is a message to the same session, so review still works without line comments.
