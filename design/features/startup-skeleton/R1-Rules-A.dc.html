Changes

#ChangeTag
1Skeleton views for the five kinds, client SwiftUI, shown before any SDUI arrives(a)
2Launch cache per window, written after each layout change once ready: section id · icon · kind · selected; sidebar shown per section, width, side; chat shown, width; workspace name; Recent count. JSON in Application Support, ≈1 KB; dropped when the app version or the plugin set changes(a)
3Kind of a pane = root node type of the last SDUI tree it showed (cached with #2). No plugin declares anything(a)
4All windows from WindowLayout open at launch in the skeleton, not after the core lists workspaces; a workspace the core no longer lists closes its window as today(a)
5Status bar start-up slot from the client’s own connection phases (process launched · socket answers · store connected) and timers(a)
6Show log: the client already starts the core; it writes the core’s stderr to ~/Library/Logs/Clubmate/core.log and opens it(a)
7Hand-over: per-window cross-fade with the 400 ms group window; reduced motion switches(a)
8⌘1–⌘9 and rail clicks during the skeleton are remembered and applied at ready through the existing section selection(a)
9Reconnecting: the client stops dispatching core-bound actions and disables their controls; scroll, selection, find stay; Retry now resets the backoff(a)
