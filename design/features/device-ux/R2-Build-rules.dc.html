Round 2 · final · build rules

Build rules and handoff

Direction A (bars fold, cards fold, columns step down), B's reading mode for wiki pages, docs and the iPad, and the round-1 navigation model, with the sections as a native TabView: Agents · Backlog · Wiki · More. Everything a builder needs to start without asking; the device boards to the left show each state. Tags: (a) companion SwiftUI only · (b) how the phone renders shared SDUI nodes · (c) what a plugin sends.

1 · Structure

  • iPhone: TabView is the root. Tabs: Agents · Backlog · Wiki · More + Tab(role: .search). Each tab = one NavigationStack, per workspace, restored on return.
  • iPad: the same TabView with .tabViewStyle(.sidebarAdaptable). Sidebar showing → the tabs are its rows (with Needs you, Inbox, workspaces below). Sidebar hidden → the system tab bar at the top. Inside each tab: NavigationSplitView list + detail. Chosen over a plain tab bar because the sidebar already existed and the tab bar alone has no room for Needs you and workspaces.
  • Workspace: a leading glass capsule (Menu) “● shop ⌄”. It replaces the Macs root screen on iPhone and today's workspace/section picker (PluginUI WorkspaceMenu, the top-bar folder button). Menu: Macs with their state → workspaces with amber counts · Mac details · Pair a Mac. Switching swaps all four stacks to that workspace's saved ones.
  • Mac details (connection, usage, paired devices, Pair a Mac, unpair) = More › This Mac and the menu row; the usage line sits on the This Mac row. Connection state: in the menu per Mac; when the current Mac is offline or unauthorized, every tab root shows C3's offline row under the title and the capsule dot goes hollow; answer buttons disable as in C3.
  • Search tab: scope = current workspace. Groups in this order: Sessions · Tasks · Wiki pages · Docs (docs.list: docs this workspace's sessions opened); 3 per group, then “Show all n”. A result pushes on the Search tab's own stack with its section line; Back returns to the results and the query. Empty field: Recent searches (5), Recently opened (5). No results: “Nothing in shop for “x”.”
  • Inbox: tray button, trailing, on every tab root (amber dot while anything waits); pushes the Inbox page on the current tab. Its “Waiting for you” group is today's Needs you. iPad sidebar keeps Needs you and Inbox rows.
  • Wiki tab only when the workspace has the wiki plugin; otherwise three tabs. Its root is the plugin's tree node; its pages are document nodes.
  • Mic: Voice is a bar button on tab roots and pages, and the first composer button in sessions. Nothing floats over content. The Search field's own mic is dictation only.

6 · Removing Docs

  • The Docs segment goes; the tab shortcuts are Agents · Backlog · Wiki · More (⌘1–⌘4).
  • Its list (docs.list: the docs this workspace's sessions opened) becomes the Docs group in Search, last after Sessions, Tasks and Wiki pages.
  • A doc link (openDoc with an absolute path + #anchor) opens in place as before, from a session, task or page: pushed on iPhone, in the detail column on iPad.
  • No Docs row anywhere, and no file browser: the app has none, and the top-bar folder button was the workspace picker, which the workspace capsule replaces.
  • Saved state or deep links that pointed at the Docs segment open the Agents tab.

Chip rule. A chip appears only when Back crosses a section or comes from Inbox or a notification; inside a section it is the plain chevron. Label = the origin's title (session title, “#4”, “Inbox”, page title), ≤ 18 characters then “…”. Long-press either = the system stack menu. On iPad the same rules apply inside the detail column, and the list column never changes on a push.

8 · New or changed components and patterns

  • (a) Tab bar (system TabView) replaces the segmented control, the bottom “Search sessions” field and the floating mic. (b) docs.list feeds Search's Docs group.
  • (a) Workspace capsule (Menu) replaces the Macs root on iPhone and the WorkspaceMenu folder button.
  • (a) Back chip: new. (a) Section line under a pushed page's title: new.
  • (a) Folded request row (56 pt): the permission card's fold-on-scroll state; the same row is the question card's bar.
  • (a) Question card: three heights full · peek · bar per the “Question card fold” ruling (B · Peek); opens at peek; one question at a time. Changes C3 “Question · composer”.
  • (a) Composer under a question = that question's Other: chip “Other · for <header>…”, placeholder “Type your own answer…”; no Queue field while a question is pending.
  • (a) Mac details move to More › This Mac and the workspace menu; offline row (C3) on tab roots when the current Mac is offline or unauthorized.
  • (a) Amber count in the session bar: replaces the request banner (changes C2 “A request arriving… shows as a banner”).
  • (a) Answered row + Next: new.
  • (a) Composer: Voice · Attach · field · Send; the “Stop is in •••” footnote goes.
  • (a) Header = back · title · up to two action buttons · •••, amending C2 “back · title · one ••• menu”.
  • (a) iPad: sidebarAdaptable sections, column step-down, reading view; list column 360 / 320 (was 380).
  • (b) header node: large title + one subtitle line, folds into the bar; actions become bar buttons; a title equal to the navigation title is drawn once.
  • (b) document node: 680-pt measure in regular width; reading mode.
  • (b) tree node: on iPad, rendered in the list column with selection following the detail.
  • (a)(b) openDoc: the phone stops intercepting it, lets it reach the section's plugin (the wiki selects its page) and pushes the result; only a file outside any section becomes a doc page. Task links stay markdown resolved against the backlog. No plugin change.
  • (c) Header actions carry a role (primary / secondary) so Edit is a bar button and History sits in •••.
  • (c) A section marks its tree as its navigation, so iPad can place it in the list column.
  • (c) Questions come as structured options with an optional suggested one.
