Rules

  • Prose = min(780, detail − 56). Side gutter 28 minimum.
  • Margin column when detail ≥ 1116 (28 + 780 + 40 + 240 + 28): 240 wide, 40 gap; prose + column = 1060, centred. The prose never shrinks to fit the column.
  • Below 1116: no column; the one-row fold “On this page · n changes · stale · n links” under the meta, as on the Mac below 960.
  • Title and meta sit on the prose's left edge, in the same column; headings follow the prose. With the column, its top aligns with the title.
  • Code and tables start at the prose's left edge. Without the column they may run wider, up to min(1060, detail − left margin − 28); with the column they stop at the prose edge. Past that, code scrolls inside its box (no wrap) with a 56-pt right fade and a scroll indicator; table cells wrap, a too-wide table scrolls.
  • Images: max prose width.
  • Reading view: bars and column hidden, prose 780 centred on the screen, code / tables up to 1060, fold row kept.
  • Column content: On this page (sticks 16 pt under the bar), In this folder, Stale, Changes, Linked from — the same sections and data as the Mac. (b) if the wiki document already carries this data for the Mac; (c) if the phone does not get it today.
  • iPhone: no change (full width, 20-pt margins). The renderer gets the detail width; compact width keeps today's path.

Why not the others

  • A · 680 always: narrower than the Mac and leaves 245–330 pt of white on each side with the list hidden — the user's complaint.
  • B · wider only past 1100: an extra breakpoint with no Mac counterpart; still ~250 pt of empty sides on 13″.
  • E · fill with 20-pt margins: 1170 pt lines ≈ 130 characters; hard to read, and code / tables lose their room.
  • D alone (680 + column): two measures across Mac and iPad for the same page.
