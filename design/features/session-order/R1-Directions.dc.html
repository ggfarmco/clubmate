C as six rules

  1. Inside a group, rows go by start time, oldest first.
  2. A new session goes last under its parent. Children and Land review fold under the session that started them, for good.
  3. Groups: main first, then worktrees in the order they were created. Closed and Service stay folded at the end.
  4. State and activity never change a row’s position, only its glyph, tint and right-hand detail.
  5. Needs you (and Open, when it has rows) is mirrored in an inbox on top, longest waiting first.
  6. Nothing you can see moves on its own.

Recommendation

C · Inbox over a ledger

  • It removes every cause in the brief. Activity never sorts. A state change never moves a row. Reviewers stay under their lander. Groups never swap.
  • It keeps what the phone is for: what needs me, longest waiting first, at the top. That’s the part the user is happy with today.
  • It covers the reach to tap: rows on screen don’t move until the user looks away or asks.
  • Both clients render one plugin tree with one meaning. Nearly all of it is plugin content (c) and renderer work (a), plus one new prop for mirror rows (b). New plugin logic (d) is only needed for the optional shared unseen dot.
Question 5

Seeing what changed without movement

  • In place, always: the glyph and the right-hand detail change where they are (“Done · now”, “Wants to run git fetch”, “Land review running”). Chip and group counts update.
  • Lasting: an accent dot on rows whose state changed since you last opened them. It clears when you open the session on either client.
  • Brief: a row that changes while on screen gets a tint (amber for Needs you, accent otherwise) that fades over 1.5 s. Turned off under Reduce Motion.
  • Waiting: the pill names what is queued (“1 needs you · 1 new”), so the user knows something will land.
  • Not used: moving rows to the top, animating rows into place, badges on group headers.
