Order and grouping, decided once in the plugin
1Sort sessions inside a group by start time, oldest first, with session id as the tie-break. Stop using last activity and newest-first everywhere.plugin(c)
2Put a new session last under its parent: its worktree group, or the session that started it.plugin(c)
3Land review is a child of its lander from the moment it starts until it is closed. It never shows at the top level.plugin(c)
4Send parents with agent-started children folded by default. The parent’s detail names them: “Land review running”, “Waiting for 2 children”.plugin(c)
5Order worktree groups: main first, then by when the worktree was created. A new worktree goes last, above Closed. If the plugin doesn’t store worktree creation, use its first session’s start.plugin(c)
6A state change never moves a row. Send the new glyph state, tint role and detail instead. Chip and group counts update in place.plugin(c)
7Needs you inbox at the top of the tree: one mirror row per session in Needs you, longest waiting first (waiting-since ascending). An Open section follows only when Open has rows. Hide the inbox when it’s empty.plugin(c)
8Mirror row: a session row that points at its session (mirrorOf: id). Selection, the keyboard and the Needs you filter treat both rows as one session.SDUI(b)
9Closed stays folded at the end, most recently closed first, 25 at a time, with Service folded after it. Unchanged.plugin(c)
10Detail wording for in-place change: “Wants to run git fetch”, “Asks: …”, “Land review running”, “Waiting for 1 child”, “Done · now”, “Started by cron”.plugin(c)

Left out of r1

  • User-pinned or dragged worktree order needs a stored order per user (d). Creation order comes first; pinning can sit on top of it later.
  • Auto-closing long-finished sessions, so Done rows don’t pile up in the tree, would be a new rule (d).
  • Whether Open joins the inbox or stays chip-only. r1 shows it in the inbox when it has rows; the 20 s event had none.
