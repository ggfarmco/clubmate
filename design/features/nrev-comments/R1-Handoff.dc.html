Recommendation: Direction A, and what to change in nrev

A tinted band is the one change that makes a comment stand out at scrolling speed without adding lines: it costs no height, survives any pane width and keeps the existing structure (below the line, ▎-style rule, header + body). B buys the same separation with two extra lines per comment and a lime frame that competes with keywords; C hides the comment above code you have not read yet and its tints collide with diff fills and diagnostic signs.

Answers

1 · A band from the code indent to the pane edge, below the line, no blank lines. 2 · Three tones by what the comment asks of you: issue amber (band, rule, title), suggestion and question blue, note neutral, praise teal; only issues get a coloured band. 3 · Icon + type bold; no author or time; keys hint only on the comment under the cursor. 4 · Resolved: one grey italic line with the first words, no band. Drifted: band stays, rule breaks ╏, ⚠ code changed. 5 · Sign ✎ and line number in the type tone; no line highlight. Blame: right-aligned, short, off in review tabs.

Checked

Contrast on the band (dark / light): body fg 11.1 / 10.9:1 on raised; warn on vt_warn 7.6 / 4.6; info on raised 7.3 / 4.6; ok on raised 7.4 / 4.6. Secondary text on a band uses muted in dark (4.7 on raised, 4.5 on vt_warn) and comment in light (4.6 / 4.6); the other way round each drops under 4.5. Band against the ground: 1.22 / 1.18:1 for raised, 1.28 / 1.17 for vt_warn.

Not coloured bands for the other types: vt_info sits on DiffChange (1.0:1) and an ok tint would sit on DiffAdd, so in diffview a blue band would read as a changed line. Even raised is 1.01:1 against DiffChange in dark; under a changed anchor line the indent notch, the rule and the bold title carry the edge. vt_ok is not used anywhere, so no new value is needed.

Extmark and virt_lines changes (lua/nrev/init.lua)

PlacementKeep virt_lines below the start line (virt_lines_above = false). No blank or padding lines above or below.
BandEach open-comment virt line = indent (spaces, no hl) + ▌ in NrevRule<T> + one space + text chunks + trailing spaces in NrevBand<T> up to the text width (winwidth − textoff). Indent = display width of the start line's leading whitespace, capped at 16 cells.
WrapWrap width = text width − indent − 3. Re-render on WinResized / VimResized (already done for wrapping). If the buffer is in several windows, pad to the widest: virt_lines are per buffer and extra cells are clipped.
HeaderIcon + type in NrevTitle<T>. Drift appends two spaces + ⚠ code changed (NrevDrift). No author or time. Keys hint ,rx resolve · ,rd delete right-aligned with one trailing space, only on the comment whose range holds the cursor: re-render that comment and the previous one on CursorMoved, debounced.
Resolution↳ + text in NrevResolution; wrapped lines indent 2 more.
ResolvedOne line, no band: indent + ▏ + ✓ <type> · resolved · + the first words of the body, cut with …, all NrevResolved. Sign ✓ NrevSignResolved, no number hl.
DriftedBand stays; the rule glyph changes ▌ → ╏; header gains ⚠ code changed; sign becomes ⚠ (NrevSignDrift).
SignKeep ✎ (not the type icon: ● ◆ in the sign column already mean info / hint diagnostics), coloured NrevSign<T>. priority above gitsigns; signcolumn=auto:2 so a git sign and the nrev sign can share a line.
Code linenumber_hl_group = NrevNr<T> on the start line of an open comment. No line_hl_group: CursorLine, Visual and diff fills keep their meaning.
Diff fillerThe other side gets the same number of filler virt lines: indent + spaces in the same NrevBand<T>, no rule, no text. A resolved comment's filler is one empty line.
Blamegitsigns: current_line_blame_opts.virt_text_pos = 'right_align', current_line_blame_formatter = '<author>, <author_time:%R>'. In a review tab nrev calls toggle_current_line_blame(false) on open and restores the previous value on close.
