A folder that has its own page

Pick C · Heading + first row. Section labels stay headings, as they are everywhere else in the app. A top-level folder's page becomes the first row under its label. A nested folder with a page is one row: chevron, folder-page icon, page title. Clicking the row opens the page; the chevron only folds. The same rule, “the folder's page is its first row”, carries over to the iPhone, which has no tree.

Answers, for C

1 · Look. The mark is the folder-page icon, so a folder with a page is visible before you hover. Its label is the page title (names over ids). A long title tail-truncates like any page row, with title and path in the tooltip. A folder whose only file is its page shows as a page row with that icon and no chevron.

2 · Selection and keys. Clicking the label or icon opens the page and unfolds the folder if it is folded; it never folds. The chevron is its own target: a 20 × 20 cell in the indent with a hover ring, which folds and leaves the selection alone. ↩ opens and unfolds. l/→ unfolds, then moves to the first child; h/← folds, then moves to the parent. j/k never stop on a section label.

3 · The page. Every page in a folder gets a caption breadcrumb above its title: “Wiki / guides /”, using folder-page titles where they exist. On an index page the margin column starts with “In this folder · n”, and the action bar adds “Page in this folder ⌘⇧N”.

4 · Companion. iPad: top-level folders are collapsible section headers with the same first-row rule. A nested folder's row opens the page, and a trailing 44 pt disclosure button folds it. A plain folder folds from the whole row. iPhone: a folder row pushes its list, and the folder's page is that list's first row, so a tap never has two meanings.

What leaks outside the wiki

  • Section labels: nothing. C removes the selectable section label the branch added.
  • Tree rows (items 7–9): every tree, on purpose. “Click opens, chevron folds, ↩ opens and unfolds” becomes the app rule for any row that has children and an open action. Today only the wiki sends such rows.
  • Header breadcrumb (item 12): a new opt-in prop on the header node. Only the wiki sets it for now.
  • Icon (item 6): one more glyph in the shared set.

Open questions

  • A root index.md: should it be the wiki's home, opened by the pane title “Wiki”? It's the same rule one level up; I'd say yes.
  • Multi-project wikis: top level is projects, so the first-row rule applies to each project's folders. Please confirm.
  • index.md and README.md both present: the brief says index wins. Should the README then show as an ordinary page?
