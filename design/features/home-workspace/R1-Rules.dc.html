Rules for Home

The a/b ruling, the glyph, how “always there, first, cannot be removed” shows on each surface, every text, and every change, tagged (a) client · (b) SDUI node or prop · (c) plugin content · (d) new plugin or core logic. Result: 7 × (a), 0 × (b), 3 × (c), 0 × (d) from this design.

Ruling

(a): first in every list, but a window can still close it

Cost S. The window model does not change.

  1. The user's rule decides it. “Home is not a different kind of workspace.” (b) gives Home its own window lifecycle: auto-open, restore, and a refused Close. A tile that ignores ⌫ is exactly a different kind of workspace.
  2. “Always there” is about finding it, not about it being open. It is met where you look for workspaces: first in Open Recent, first on Welcome, first under each Mac on the phone, and ⇧⌘H from anywhere. None of these can lose it: no cap, no Clear Menu, no trash.
  3. Windows are for focus. A window opened for shop should not carry a Home tile, Home terminals and Home agents it did not ask for. With (b), Home is open in N windows at once, and every window's restore brings it back.
  4. One rule fewer to explain. With (a), × and ⌫ behave the same on every tile. With (b), we need a disabled ×, a refusal message and a Close Workspace exception, all for one workspace.
  5. Cost. (a) is list ordering and menu drawing, all in the client. (b) touches window creation, state restore and the close path (M/L).

What (a) gives up: in a window where Home was never opened, the switcher has no Home tile. I chose not to fix that with a ghost tile, because that is (b) by another name. ⇧⌘H opens Home in the current window in one key, and from then on it leads that window's grid.

Glyph

SF Symbol house, outline, muted

Home Home
Home Home
  • Mac: house drawn at the label's size: 12 in tile labels and the title bar, 14 in Welcome and Open Recent. Text level is muted; the name next to it stays fg.
  • Phone and iPad: Label("Home", systemImage: "house"). When selected, the system checkmark replaces it, as it replaces folder today.
  • Never house.fill, never accent or a tone (colour is state, and Home is not a state), never the gourd mark (that is the brand), never “~”.
  • The glyph marks Home, so it survives a rename. A Home renamed “life” still shows the house.
  • Why not a pin. A pin says “the user chose this” and invites unpinning. Home was not chosen and cannot be unpinned, and “never a badge for pinned alone” rules out the alternative anyway.

Not doing

  • A Home tile in windows where Home is not open: that would be (b) by another name.
  • Folder icons on the other recents to match Home's glyph.
  • A “pinned”, “always” or lock badge anywhere.
  • Prefilling or sending “What waits for me today?”. It is suggested in text only.
  • A Home row in the phone menu built by the client when the core sends none.
