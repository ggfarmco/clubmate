How the screens connect

A cron job or a trigger starts sessions; a trigger fires on a session's turn or on an event it emits; a task is owned by a session or a graph run. Each screen draws its own piece of this picture and links to the rest by name.

Rules

1

Colour is state.

Accent marks the last move, this trigger, the selected card or run. Amber only for missed runs and needs-you. Red for failed. Running is the accent play glyph; ok is teal.

2

The primary action follows the state.

Cron: Run now, or Resume while paused. Trigger: no primary when a graph owns it (Run now, Pause, Open graph G; Delete only in ••• with a warning). Task: Start agent while you own it, Open ‹owner› ⌘↩ while a session or graph run does, Take back returns it to you.

3

Results in words.

“main is green · 14 checks passed”, “prompted Reviewer · its turn 2 started”, never null or a JSON blob. Consecutive identical results collapse to one row with ×N.

4

Missed is separate from When missed.

The missed run is a warning strip with Run it now; the policy is a select. Paused jobs say “none while paused”, the strip hatches the paused span.

5

Owner nobody.

Failures go to the inbox; ok results stay in Runs. (Proposal: the build says every result goes to the inbox — that floods it at every 2 min.)

6

Names over ids, links over text.

Sessions, graphs and tasks appear as owner chips that open the thing: Review loop · Coder, graph Review loop, backlog #2.
