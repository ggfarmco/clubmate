Clubmate · themes · reference

How nvim takes colour — Light Owl as the example

Every role an nvim theme has to fill, the highlight groups each role paints, and what Light Owl puts there today in Clubmate's nvim. A Clubmate theme for nvim is one value per role, dark and light. Values read from the running nvim, not from the theme file.

Light Owl today

Where the colours come from

  • Terminal: the Ghostty theme — 16 ANSI colours, background, foreground, cursor, selection. nvim's own terminal gets the same 16.
  • Syntax: a bundled colorscheme sets every syntax and editor group explicitly (colors/lightowl.lua today).
  • Clubmate layer on top: floats, picker, completion, which-key, git signs, diff panel, file tree, notifications and lualine are repainted from six roles — accent, success, warning, danger, selection, muted — so they match the app.
  • Today those six come from ANSI slots (accent = 4 blue, success = 2, warning = 3, danger = 1) and fixed blends of text into background. A Clubmate theme sets them directly.

What Light Owl gets wrong

  • Comments and line numbers 2.6:1; warning yellow and git “changed” 2.0:1; whitespace and inlay hints 1.4:1 — unreadable.
  • One pink for keywords, operators, numbers, macros, headings and TODO: no rhythm in the code.
  • One teal for types, modules, builtin variables, attributes and hints.
  • Two selection blues: Visual vs the menu and picker row.
  • Folded, ruler column, diagnostic ok and Added/Changed/Removed fall back to nvim's defaults; markdown code and quotes have no colour.
