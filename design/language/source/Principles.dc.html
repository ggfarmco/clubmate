Clubmate · design language

2 · Principles

Six rules for settling arguments. When a plugin view and a principle disagree, the principle wins; when two principles disagree, the earlier one wins.

1

The palette is borrowed; the proportions are ours.

No hex values in the UI. Every colour is a role: fg, bg or a tone at a fixed ratio, computed once per theme. If something looks wrong in one theme, fix the ratio for every theme, never the theme.

Decides: “can this plugin use orange?” — No. It can ask for tone: warning.

2

One line per thing.

Rows are one rowHeight tall. Space separates groups, never items. A second line is allowed only where you compare items by more than their name: notifications, and properties in a detail view.

Decides: “should session rows show a preview line?” — No. Show state as an icon, put the rest in the detail.

3

Colour is state, never decoration.

accent = focus, selection, the one primary action. warning = needs you. danger = failed or destructive. success = finished, shown once, then fades to muted. Everything else is fg at a text level.

Decides: “should the running agent be green?” — No. Running is normal; only waiting, failed and done-unseen get a tone.

4

Cards are for things that ask or change.

A plan, a diff, a permission request and the composer get a surface. Lists, properties, messages and settings stay flat on the pane. If you are reaching for a card to group things, use a section label instead.

Decides: “should cron properties sit in a card?” — No. Flat property list; the card budget is spent on what needs a decision.

5

Every action is visible once and has a key.

If an action is in a context menu, it is also in the pane's action bar or the palette, with its shortcut printed next to it. Focus is always visible: a ring on the focused pane's cursor row, selection fill everywhere else.

Decides: “Pause lives in the right-click menu, is that enough?” — No. Action bar, P.

6

Names over ids; keep the end that differs.

Show what a person named or what the thing does; ids go in “Copy id”. Truncate titles at the tail, paths in the middle, commands keeping the executable and the last args.

Decides: “the trigger has no name” — the plugin writes one: “Review loop: Coder done → Reviewer”.

Brand

Where the mate green belongs

Not inside a themed window. The user picked their colours in Ghostty; a second green would compete with their success tone and make “done” ambiguous. The brand lives where the theme doesn't.

Yes

  • App icon, Dock, About window
  • First run and onboarding: the one screen with no Ghostty theme yet
  • The Mate fallback theme, used when no Ghostty config is found (replaces Kanagawa)
  • Website, docs, release notes
  • Monochrome gourd mark in empty states, drawn in muted fg, not green

No

  • Accent, selection or focus colour when a user theme is active
  • Success or “connected” indicators
  • Title bar, rail or status bar tint
  • Gradients anywhere in the window

The Mate fallback theme

Derived from the icon: calabash cream, yerba lime, teal for success so it never reads as the accent. It goes through the same role formulas as any Ghostty theme. Accent and tones are the same values as the companion app (C2), so Mate green, amber and red match on the Mac, iPhone and iPad; only the grounds differ — calabash here, system surfaces on the phone.
