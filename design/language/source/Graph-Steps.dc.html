Steps: nodes Clubmate runs itself

A step is a command, not a person: a check whose exit picks the next edge, or an action. Its result is what the command returned, so it never forgets, runs the wrong thing or says green when it isn't.

Rules

1

Shape, not colour, tells the kinds apart.

Agents are round cards (10 px) with a sparkle; steps are square (3 px) with a left rule and their command on a mono strip under the name. A small word at the right says agent, check or action. Phones: round state badge for agents, square for steps.

2

A step's ports are its outcomes.

Checks have pass, fail and any named outcomes from the step's exit codes; every step has error. Error with no edge stops the run and needs you.

3

Approval is a permission request.

A command nobody pre-allowed waits: the exact command, the folder it runs in, Allow once ⌥1 · Always allow… ⌥2 · Reject ⌥3 (decision 1 wording; Reject ends the step with error · rejected). Always allow… asks first (decision 2).

4

Output tail where you look after fail.

Selecting a step opens its output panel beside History: the last lines (7–12), exit code and duration, Full output ⌘O (a read-only terminal pane), Copy. A fail edge passes the tail to the next agent with its prompt. Empty output says so, with the command and folder.

5

Caps live on edges.

“at most N” in the definition; ×n/N on a run. When the cap is hit, the edge turns amber and dashed, the run waits for you: Continue ⌘↩ allows one more round, Stop run ⌘..

6

Trust before running shell steps.

A graph file whose steps changed since you trusted it is untrusted: Run becomes Trust… ⌘↩, which lists every command and marks what changed. Trust lasts until the file changes. Allow lists still apply.

7

History: steps are bars.

A step's move lasts from start to exit and is drawn as a bar on its lane, labelled pass / fail / outcome with its duration; running and waiting bars are open-ended. Rounds get a bracket, so tests → coder → tests reads as a loop.
