Clubmate · design language

6 · Handoff & open questions

Most of this is client-side: tokens and renderers. Plugins mostly need better words. Four SDUI additions, each named below with the problem it removes.

a

Theme tokens & renderers — Theme.swift and the node renderers

  • Add surface-1/2/3, text-2, faint, border-strong, hover, pressed, selected-idle, focus ring, tone-bg/border/ink, on-accent. Compute text-2, muted and tone inks per theme against contrast targets.
  • Selection: accent 20% + bar (was fg 6%). Add the unfocused-pane variant.
  • Type: add heading (u + 4); count glyph max(9, u − 2). Spacing: xl, xxl, section. Radius scale. Control height 2u. Rail 40.
  • Button renderer: 24pt, keycap inside, loading label, focus ring; variants, disabled and shortcut arrive with the (b) props below.
  • Field/select/toggle renderers: sunken bg, border-strong, focus halo, error caption.
  • Transcript: user message tint, thought row, plan without strikethrough, tool group summary, silent success, failed rows inline.
  • permissionCard: docks above the composer while pending; new keyboard handling — ⌥1 ⌥2 ⌥3 in button order, always, without touching the draft; bare 1/2/3 or y/n when the composer is empty or the card has focus; ⎋ stops the turn, never rejects. Collapses to a row when answered.
  • Composer: one footer layout; primary follows state; Stop moves to the pane header (⎋); the mode menu reads Ask before edits · Plan · Accept edits, never a bare “Default” — same label in the session header.
  • Pane header: measured height, single-line title, meta moves to a second line below 800pt.
  • Window chrome: themed title pills in the terminal font, warning count, status bar content, rail attention dot.
  • Palette: right column = keycaps only. Notifications: SF Symbols in tones, two-line rows.
  • Below 800pt: sidebar overlay on ⌘B, breadcrumb row, action overflow menu.
  • Fallback theme: Mate dark / light instead of Kanagawa.
c

Plugin content

  • agents: one tree grouped by worktree (branch name only); graph sessions nested under their graph; filter row instead of the “Needs you” section; badge only for waiting / failed.
  • cron: header + action bar + properties; schedule in words with the cron expression muted; prompt as text, JSON behind a disclosure; runs list with an empty state.
  • triggers: names that say what happens (“Review loop: Coder done → Reviewer”); When / Then sections; ids only in “Copy id”.
  • backlog: detail pattern; priority as a glyph before the title; autosave; Start agent as the primary.
  • processes: group rows by owner; totals as a header strip; auto-kill into options; selected-row action strip.
  • graphs: run header with turn progress; node list with state next to the label; diagram at ≥ 800pt; teaching empty state.
  • terminals: drop “running”; show exit codes, bells, idle time.
  • code chat: one picker row as the header; empty state with context chip and three starters.
b

New SDUI props / nodes — four, deliberately

AdditionWhy it can't be (a) or (c)Used by
header { icon, title, badges[], actions[], meta }The detail pattern needs header + action bar to behave identically (wrapping, overflow menu below 800pt, key hints). A stack of text + buttons can't carry that contract, and the 640 overlap bug came from exactly this.cron, triggers, backlog, graphs, agents
button { variant: primary | secondary | ghost | danger, disabled, shortcut }Today a button has only label, icon, confirm and action. The renderer can't guess which button is primary or destructive, can't show disabled, and keys must be printed from data. Reuse the vocabulary permissionCard already has in its option kind.every plugin
table column { truncate, align, priority }Middle-truncated paths, right-aligned numbers, and which column drops first when narrow are per column, not per table.processes, future tables
empty { icon, title, action, hint }Today empty is text only. The teaching empty state needs an icon, a title, one action and a code hint in fixed places.graphs, triggers, backlog

Suggested order

  1. Contrast-computed text levels + new surface/state tokens (fixes P0 #3, unblocks everything else).
  2. Pane header measuring + permission docking and its keys (P0 #1, #2).
  3. button / empty protocol props, then the button and field renderers.
  4. header node, then cron → triggers → backlog onto the detail pattern.
  5. Agents sidebar content, chrome pills, status bar.
Decided
  • Mode label. “Default” is the session mode (Default · Plan Mode · Accept Edits). Show it by meaning — Ask before edits · Plan · Accept edits — in the header and the composer menu.
  • Permission keys. ⌥1 ⌥2 ⌥3 in button order, always; bare 1/2/3 or y/n only with an empty composer or a focused card; ⎋ stops the turn and doesn't reject.
  • Protocol. button is label / icon / confirm / action; empty is text. Both extensions go through (b).
Open questions
  1. Settings window. Keep it a native SwiftUI form (system font, system look) or move it into the main window as an SDUI pane in the terminal font? I lean native for the window, but themed and grouped like the detail pattern.
  2. Which light themes do your users run? I tested Catppuccin Latte. Worth running the token formulas against two or three real Ghostty configs before locking the ratios.
  3. Fallback theme. OK to replace Kanagawa with Mate dark / light?
  4. Notify on “done”? I kept done notifications in “Earlier” without a badge. Should they notify at all, or only waiting and failed?
  5. Task numbers. Is #n a stable handle people type (e.g. in cm commands)? I kept it as muted detail in the list and next to the title; if nobody types it, it can go from the list.
  6. Does Start agent use the description as the prompt? If yes, the description field should say so; if not, what does the new session start with?
