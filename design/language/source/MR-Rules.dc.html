Clubmate · Agents · tasks across repositories

One task, several repos

No project entity: a workspace is a list of folders, and a task that needs another repo asks for it once. The tree names children by their repo, a live Repos card says what landed, and the title pill shows the folders the workspace gained.

Decisions

1 · Connecting a repo

A Connect a repo? card in the transcript — one card for every repo Claude has found so far (“Connect 2 repos?”, each ticked, Space un-ticks) — in the permission card's family (amber outline, ⌥1–3), one size up: the repo's name large, its path, remote, branch and clean state, Claude's reason quoted, a warning when the clone is dirty or behind origin, and what a yes does — becomes a folder of the workspace and stays; a child session on a new branch with that repo's own rules and memory; how it lands. Connect ⌥1 (the ticked ones; un-ticked ones are skipped, not left pending) · Don't connect ⌥3, with what that means under it. Each row has its remote and its own “other folder…” (⌥2 on the focused row). Each row says how the repo lands and where that rule comes from (its CLAUDE.md); a repo's own rules win over the plan. A repo found later gets its own card. A repo connected by AFK never merges in that run: it opens a PR at most. No Always: a folder is asked for once. It is a needs-you state with no time limit — the session, its row, the bell and the phone's Needs you show it — and never a system alert. If the repo isn't on disk the card says “Clone github.com/acme/internal-auth into ~/develop/acme?” and Connect becomes Clone and connect. Boards: MR-Request-1280-Mate, MR-Request-640-MateLight, C-MR-Request.

2 · The tree by repo

A child that works in another repo is named by its repo: folder glyph + repo name, the state at the right. Its task text moves to its own header. Children hang off the parent with a guide line, and the parent's right side sums them up (“8 repos”, “1 failed”, “waiting”), so they read as one task. Holds at 640 with 8 children (MR-Tree-640-MateLight). A repo with two children falls back to “repo · task”. A repo waiting to be connected shows as a child row in amber, “connect?”.

3 · The task at a glance

Yes, worth it: a Repos card under the orchestrator's latest report, owned by the plugin, not written by the agent, and live. One row per repo: order, repo, branch, how it lands (pull request · stays on its branch · merge), its state (landed · PR open · on its branch · ready to land · failed). The footer says the order and the finish mode; Order follows dependencies (storage → auth → API) and a repo lands only after the ones before it landed, so a failure holds everything after it. A failed child counts in Needs you: the child is red, the parent amber. In “ask before merging” the next repo in order has the action (“Review and merge internal-auth…”). The failed row opens by itself: the failing tail and its own actions (Ask it to fix ↩, Open its session, Open in Code, Leave it unlanded… at the far end, with what that holds). The session header carries one pill, “3 repos · 1 failed ▾”, that opens the card wherever the transcript is. It collapses to one line (“3 repos · 1 landed · 1 on its branch · 1 failed”) once you've read it. Boards: MR-Task-1280-Mate, MR-AFK-640-MateLight, C-MR-Task.

4 · A workspace that grew

Three places, nothing behind your back: the moment — a system row in the transcript, “Connected internal-auth · you · now a folder of ads” (AFK: neutral, an AFK badge, one action — Remove from ads…; doing nothing keeps it); the title pill — “ads +1” until you open its picker; Code — nvim shows one folder at a time, so the title picker, where the worktrees were, picks the folder too: worktrees grouped under their folder, the open one ticked, the added folder marked “new” with who added it, and Remove ‹folder› from ads… at the bottom. The pill reads “ads +1 / internal-auth ▸ main”. Removing never deletes files; it is refused while a child still runs in that folder. The status bar says “internal-auth ▸ main · ads has 3 folders · 1 new”. Board: MR-Code-1280-Mate.

6 · Cleaning up

Archive task… lives on the parent row's menu and in the Repos card footer once every child is done; never automatic, never during a running child. The sheet shows, per repo, what happens to the worktree and to the branch and why: a merged branch is deleted locally (git's own branch -d rule), a branch with an open PR or a rule to stay is kept, a dirty worktree or one open in Code is kept (amber, “Remove it anyway” unticked). Remote branches are never touched; transcripts stay; sessions move to Closed, and Restore brings them back. Cron jobs that run in a worktree that goes are named and pause. “Close sessions only” keeps every worktree and branch. Archive is plain while nothing is lost and turns red when “Remove it anyway” is ticked. An optional, unticked “Also remove ‹folder› from ads” appears for a folder the task added and nobody else uses. Leftovers from other tasks: Clean up worktrees… in the title picker, grouped by the task that made them, merged-and-clean ticked, the rest yours to tick. Boards: MR-Archive-1280-Mate, MR-Sweep-640-MateLight, C-MR-Archive.

7 · The other sections

One rule: everything has a home, the workspace or a folder. Arrive and leave with a folder (they live in the repo): graphs (.clubmate/graphs/), worktree hooks, CLAUDE.md, skills and other agent instructions. Belong to a folder through a session: agent sessions and their worktrees; each folder's selected worktree. Per repo in the app, outliving a removed folder: trust for graph steps and hooks (repo + content hash). Per workspace, untouched by folders: Backlog, Cron, Triggers. So the connect card says what a repo brings — graphs, hooks, instructions — and that steps and hooks stay off until trusted; the Remove sheet lists exactly sessions, worktrees, graphs, hooks and instructions, and says Backlog, Cron and Triggers are untouched (MR-Remove-1280-Mate). Two proposals, new fields: a Backlog Repos field — empty means the workspace, as today; several repos make Start agent start an orchestrator; attachments name their folder (“ads-management ▸ docs/pause.md”) instead of being relative to the first folder (MR-Backlog-1280-Mate). And Cron's and Triggers' “Worktree” becomes Runs in ‹folder ▸ worktree›, the title picker's list; existing jobs read as the first folder; the list groups by folder once there are two (MR-Cron-1280-Mate).

9 · One name per task

A task uses one slug everywhere: branch feat/campaign-pause-reason and worktree .worktrees/campaign-pause-reason in every repo, unless a repo's own rules name branches differently (its rule wins). The Repos card says it once in its header instead of a branch column; search for “pause” finds the task as one row; archive and clean-up rows read as one task. The Mac gets the ask-before-merging card too: Land internal-auth? with Review… ⌥1 (opens the diff; ⌥1 is the muscle-memory “yes”, so it never merges by itself), Merge ⌥2, Leave it unlanded… ⌥3 at the far end with what it holds (MR-Merge-640-MateLight).

8 · Hundreds of worktrees

A repo can already hold hundreds of worktrees, so the title picker never lists them all. Up to about 20 in the whole workspace it lists everything, grouped by folder (MR-Code-1280-Mate). Above that it opens on a search field and capped sections: Now (the open one), Live (a session runs or waits there — never capped), Recent (opened in 7 days, at most 6), and Folders with counts (“214 worktrees · 2 live”), → opens one (MR-Picker-1280-Mate). Inside a folder: Live, Recent, By task (closed sessions, newest first, first 2 shown), Made by hand and Stale (merged, or no commits for 30 d) folded with counts, Stale with “Clean up 163…” (MR-PickerFolder-1280-Mate). Typing searches every folder by folder, branch, task and session name; a task is one row for all its folders; live first, stale last (MR-PickerSearch-640-MateLight). Clean up groups by what removing costs: merged and clean, PR merged with the remote branch deleted (ticked); PR closed without merging (never ticked — the only copy is local); idle but pushed (yours to tick); unpushed or dirty and made by hand (no group tick, one at a time, the row turns red and names what is lost); live ones and any open in Code are never listed. The button is plain while nothing is lost and turns red with the loss in its name (“Remove 138 · lose 3 files”). Cron jobs that run in a listed worktree are named and pause. Counts reconcile: 191 = 182 stale + 9 made by hand (MR-Sweep-640-MateLight).

5 · Phone

The same card in the session's bottom bar, with its landing rule; another folder is picked on the Mac (C-MR-Request); in the workspace list the orchestrator sits in Needs you with “Wants to connect internal-auth” and its children nested under it by repo (C-MR-Workspace-Light); the session shows the Repos card; the landing action is a plain “Review and merge internal-auth…” that leads to a screen with the commits and its own Merge, so it never looks like Connect (C-MR-Task).

Handoff

aTree rows for children in another repo: folder glyph + repo name as the label; guide line; parent's summary at the right.
aConnect card style (permission family, one size up); the AFK system row; the “+1” on the title pill; the title picker grouped by folder, with “new” on an added one.
brequest.connectRepo node: name, path, remote, branch, clean, reason, what-happens lines, buttons; phone draws it natively.
brepos node: rows (order, repo, branch, lands-by, state, action) + footer; collapsed state.
cOrchestrator instruction: one sentence of why per repo; name children by repo; AFK reports say which repos it connected.
cWords: “Connect a repo?”, “Another folder…”, “Don't connect”, “Switch folder, worktree or branch”, “Add a folder to ads…”, “Remove ‹folder› from ads…”, landing states as on the boards.
dConnect request as a needs-you state with no timeout (Mac + phone), routed to the orchestrator; a child's request goes to its parent.
dWorkspace folders: who added each and when; removal (refused while a child runs there); “new” until seen.
dPer-repo landing state for the Repos card (from each child + git/PR state), the order, and the finish mode's ‘ready to land’ action.
dClone-and-connect when the repo isn't on disk (never in AFK).
dLanding: a repo lands only after the ones before it; AFK-connected repos land by PR at most in that run; one task lands per folder at a time.
dArchive: per-repo plan (worktree, local branch, why), git branch -d rules, refuse while a child runs or a worktree is open; Restore from Closed.
brequest.connectRepo rows: remote, landing rule and its source, per-row other folder; skipped vs pending; what the repo brings (graphs, hooks, instructions) and their trust.
dRemove folder: list sessions, worktrees, graphs, hooks, instructions tied to it; keep per-repo trust; Backlog, Cron, Triggers untouched (today).
dPicker at scale: per-worktree last-opened time, live state, owning task, made-by-hand flag, stale test (merged, branch gone on remote, idle 30 d); cross-folder search over folder, branch, task, session names.
dProposal: Backlog task repos field; attachments as (folder, path), migrating today's paths to the first folder.
dProposal: Cron and Triggers runsIn = folder + worktree (replaces Worktree; existing = first folder); a removed folder pauses its jobs and triggers.
dBatch connect: one request carrying several repos, answered per repo; clone health (dirty, behind origin) in the request.
aTree: fold a finished parent once opened; pin a child that needs you or failed; stable landing order; ⌥↑ ⌥↓ between siblings.
brepos node: an expanded failed row (tail lines + row actions) and the header pill that opens the card.
