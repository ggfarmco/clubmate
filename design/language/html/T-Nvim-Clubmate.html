Clubmate · themes · nvim

T3 · Clubmate for nvim — every role, dark and light

The nvim side of Clubmate / Clubmate Light, filled role by role from the map in T2. Same Mate palette and syntax roles as T-Themes and the Ghostty pair; one value per role in each variant.

Accent in the editor chrome: lime

Mode block, float titles, matches, which-key keys, the current search match and the cursor line number use Mate lime, the same accent as the app around the editor. ANSI slot 4 blue is a terminal colour for programs to use, not our accent; in the editor blue means types, info and “changed”.

Types don't share the warning amber

Amber in the editor means one thing: a warning (plus TODO). Types move to blue, so a warning undercurl on a type is still visible. Modules share the type blue; builtins take the function teal in italic. T-Themes updated to match.

Diff fills: 15%, words 28%

Added and deleted lines use the app's 15% tone fill (decided over the cards' earlier 13%). A changed line gets 10% blue, so the 28% changed-words fill stands out on it. “Changed” is blue everywhere — signs, tree, diff — not amber.

Ships as “Clubmate” and “Clubmate Light”

Our loader, colors/clubmate.lua, applies the scheme, so they ship as two themes by name, matching the Ghostty pair. T-Themes' file line now says so; no separate plugin.

What changes against Light Owl

  • Contrast: every text role is ≥ 4.5:1 on the background (most ≥ 5:1) and stays ≥ 4.5:1 on the cursor line; comments 5.3 / 5.4:1. Line numbers and inlay hints ≥ 3.8:1 — secondary, but readable (Light Owl: 2.6 and 1.4).
  • One hue per job: lime keywords, teal functions, blue types, sand strings, lilac numbers and constants — no hue does two unrelated jobs (Light Owl: one pink for keywords, operators, numbers, macros, headings and TODO).
  • Selection ≠ search: selection is the app's accent fill, search is blue, the current match is solid lime (Light Owl: the same pale blue for both).
  • Nothing falls back to nvim defaults: folds, ruler, ok, Added/Changed/Removed, markdown code and quotes all have values.

Roles

Contrast is against the editor background. Blocks (cursor, current match, modes, TODO) show their text on the fill. Marks (whitespace, separators, borders) are non-text and faint on purpose; the rest are fills.
