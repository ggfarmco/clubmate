Reviewing an agent's changes

nvim keeps the code: two Diffview panes in the Clubmate theme, comments as wrapped virtual lines. Everything about the review itself — progress, files, comments, sending them back — moves into a native Mate panel in the Code section, driven by the diffview fork's host API.

Why a native panel

  • The header can stay pinned, filters can be real controls, and rows can say what they mean, with tooltips. The nvim tree is a buffer: it scrolls, truncates and can only use letters.
  • At 640 the panel folds into a drawer and a one-line strip, so nvim keeps the full width.
  • The done moment and Send to Claude are app actions: they talk to the session that made the changes, and the Agents screen shows the same state.
  • The host API already has what the panel needs: open, list entries with reviewed / stale / comment state, select, toggle reviewed, next unreviewed, filters, hide the panel, subscribe.
  • Nothing is lost in nvim: r, ]f, ,rc, ]a, ,rx and ,rl keep working, and the panel follows them.

Where it lives

  • The Code section's right column has two tabs: Review | Chat (⌘B switches). Review is there while a review is open; closing it brings the chat back.
  • Entry stays the same: Review changes in the session header, Full diff ⌘D on an edit card (which opens that file).
  • Agents: a session with an open review shows it in its row (“review 5/15 · 1”) and in its header (“Review 5/15 · 1 issue”, Open review ⌘R). After Send, the transcript gets a Review card (comments, file:line, your note) and the header reads “Review 15/15 · 3 comments sent”. Files the agent then changes turn ● in the review.
  • Send goes to the session that made the changes; if it is gone, Send offers a new session in the same worktree. Copy ,re stays for other tools.

Handoff

a nvim review profile: tabline off, absolute numbers, winbar format, comment virtual lines with wrap and opposite-side filler, inline layout under 900 pt, new/deleted fills and labels. Colours are T3 (DiffAdd teal 15%, DiffDelete red 15%, DiffChange blue 10%, DiffText blue 28%).

b Native panel on the host API: header, tree with state/kind/comments/counts, filters, comment list, footer with keys, Send and Copy; the 640 strip and drawer.

c The review skill receives the comments as a Review message (structured: file, line, type, text, plus your note), marks them fixed as it works, and leaves resolved ones alone.
