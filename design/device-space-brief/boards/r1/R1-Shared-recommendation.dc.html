Handoff

(a) companion SwiftUI only · (b) how the phone renders shared SDUI nodes · (c) what a plugin sends

(a) Session bar: other sessions waiting = amber count; drop the 56-pt banner. Tap pushes that session with a back chip.
(a) Docked permission and question cards: folded 56-pt row while scrolled back; full at the live end or on tap. The row never answers.
(a) Question card: one question at a time, 46-pt option rows, auto-advance, Send after the last; typing answers the current one.
(a) Mic: bar button on reading screens, composer row on sessions. No floating mic.
(a) Navigation: one stack per section and segment, restored on return. Cross-section links push into the current stack with a named back chip, a section line and ••• › Show in <section>.
(a) Entry points: Needs you, Inbox and the request banner push with a back chip; a lock-screen notification builds Macs › workspace › session.
(a) Answered card: one muted row, then Next waiting or Back in the bottom 40%.
(a) iPad: column visibility per section (all · list + detail · detail), sidebar button and ⌃⌘S; portrait opens detail-only with the list sliding over.
(a) iPad reading view on ⌃⌘F / pinch out; Esc or edge swipe restores the previous columns. No auto-hide with VoiceOver, Switch Control or Reduce Motion.
(b) header node: large title + one meta line at rest; folds into the bar title after 44 pt; its actions render as bar buttons, primary first, the rest in •••. Applies to the wiki and every plugin section header.
(b) header node: when its title equals the navigation title (the wiki list's “Wiki” twice), render it once.
(b) document node: 680-pt measure in regular width (doc and wiki pages, sheets); reading mode that hides chrome on scroll, tap to bring it back; headings feed a contents button.
(b) link inside a document: the result pushes (iPhone) or opens in the detail column (iPad), never a full-screen popup; a file outside any section opens as a doc page with a 680-pt measure.
(b) tree node: on iPad, render in the list column with selection following the detail; on iPhone, a pushed list as today.
(a) (b) Link routing needs no plugin change. A document link fires openDoc with an absolute path (+ #anchor). The phone stops intercepting it and lets it reach the section's plugin: the wiki already maps the path to its page and selects it, and the phone pushes the result. Only a file outside any section falls back to a doc page. Task links like #4 stay markdown that the phone parses and resolves against the backlog.
(c) Header actions carry a role (primary or secondary) so Edit goes in the bar and History in •••.
(c) A section with its own navigation tree marks it as the section's navigation, so iPad places it in the list column.
(c) Questions arrive as structured options with an optional suggested one (for the one-at-a-time card).
