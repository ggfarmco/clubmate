Your four questions

1 · Names

See the table: the dock row is Gates; the points are Landing, Done and Tool call; a gate is named by its point and its match.

2 · Match without regexes

Presets first, Custom… last; regex only appears inside Custom… for a tool call. Under every match the sheet shows what it resolves to (“= Bash · the command starts with git push”) and a dry run from the last 7 days (“9 calls would have been held”), so a match is checked against real work, not read as a pattern.

3 · One held state or three

One (A). Whatever a gate holds — a landing, a done turn, a tool call — reads held in accent with a shield glyph: a graph is working and nobody has to answer. The gate run hangs under it: a one-node graph as “Round 1 review” (as today), a longer one as “Plan pipeline · round 1” with its nodes folded under. What is held is said where there is room: the transcript's held block, the phone row's subtitle (“Held · git push · Fable review…”), the session header badge (“held · git push”). A held tool call is never a permission card: no buttons, nothing to answer.

4 · The graph on the gate page

A node list (A): numbered steps with their kind and what each does, then “ends approved · changes”, the pinned version and Open graph. The diagram stays on the graph's own page; B's mini diagram is drawn for comparison.

The design, part by part

The sheet

New gate / Edit gate (GT-Sheet-*): Repo · Holds · the match fields of that point · Decided by · Rounds (1–5). The Decided by list groups Built in / Yours / In ‹repo›, shows each graph's chain, and greys a graph that doesn't end with approved / changes. The chosen graph's chain shows under the field. The footer says the gate in one sentence. ⌘↩ creates, ⎋ cancels.

The dock

Gates unfolds into repos, then gates (A). Row detail, by priority: trust? amber (graph changed; counts once in Needs you) › 1 asking plain (the card is on the held session) › reviewing / N held accent › paused muted › last verdict and age, plain. The Gates row itself shows the highest of these across all gates. Up to 6 rows, then it scrolls.

The gate page

Header: the point's glyph, “Done · plans and specs”, gate · active, last verdict; Pause P, Edit E, Delete ⌘⌫. Facts: Repo, Holds, Match, Graph (node list), Rounds, and for a landing Docs only. History: when · verdict · what was held · round · findings · Open run; an approved row carries its summary under it in caption ink. A selected changes row opens its findings, deferred items last. When the graph changed, a trust card sits on top: the diff, Trust and run ⌘↩, Open graph, Pause the gate.

Held, per point

Landing: as today. Done: the turn is over but not done for anyone — no done, no Needs you, no notification until approved; changes send the findings back to the agent as a message from the gate, and its next done is round 2; approved makes it done and opens what it asked to show. Tool call: the agent waits inside the call; approved runs it. Changes refuse it — a plain refusal, because Claude Code passes no reason with a refused permission — and right after it the gate sends the same message as for Done, “From the gate · ‹gate› · round N · changes” with the findings (GT-A-Refused-640-MateLight); the next matching call is round 2. While a gate waits for trust, what it holds keeps waiting; the child row reads “waits for trust”.

Rounds used up

One card for all points, docked on the held session like today's, counted once in Needs you: “‹graph› still asks for changes after N rounds”, the last findings and the summary, then the point's verb — Land anyway / Accept as done / Run anyway ⌥1 — One more round ⌥2, and Stop ⌥3 at the far end.

Phone

Gates in the Agents list opens the Gates screen grouped by repo, and each gate's page, both SDUI. Held rows stay under Running with “Held · what · who decides”. The card reads as on the Mac. Pause works on the phone; New, Edit and Trust stay on the Mac, because they need the sheet and the graph's diff.

Handoff

aPoint glyphs (merge, done bubble, terminal). The held state: shield glyph and accent “held” on tree rows and phone rows; the session header badge “held · ‹what›”; “messages queue” in the composer.
aPhone: held rows, the held block in the native transcript, the rounds-used card with three answers.
bSheet controls if the catalog lacks them: a segmented control (Holds), toggle chips (Sessions, Call presets), a stepper (Rounds), a select with grouped, described, disabled items (Decided by).
bA step chain: node chips with state (running, done) for the held block and the sheet; falls back to text “Fable review · reviewing”.
cWords: Gates, Landing, Done, Tool call, Holds, Decided by, held, “Held by a gate”, “waits for trust”, “Accept as done”, “Run anyway”, “One more round”, the per-point sentences under Holds, the preset names.
cGrouping and order: the dock and the phone Gates screen group by repo; inside a repo Landing, Done, Tool call; the gate page's facts, node list and history with summaries; the dock row's detail priority.
dGate model: point × match × graph, several per repo; the most specific match decides and only one gate runs per held thing (landing: exact branch › pattern › base › default › any; done and tool: a named pattern › any); the sheet refuses an exact duplicate.
dHolding: the done turn (done, Needs you and notification wait) and the tool call (the agent waits inside it). Changes always reach the agent as one gate message with the findings; for a tool call it follows a plain refusal, since Claude Code carries no reason with it. Rounds per point; One more round (⌥2).
dGraph pinning: a gate pins the graph's content; a changed file puts the gate in “trust?” and holds wait; Trust and run re-pins.
dHistory: each run's verdict, findings, deferred items and summary; the summary also goes into the landed commit's body.
dLater slice: the dry run under the match, “N would have been held in the last 7 days”. It stays in the design; the sheet works without it.
