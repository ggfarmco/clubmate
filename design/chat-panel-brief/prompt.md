Hi. This canvas is a new feature for Clubmate: the agent chat panel, the same in Code (nvim) and in Wiki. Page "today" has real screenshots from the test app (Main: Mac Code 1280 and 900, Mac Wiki 1280, iPad Wiki from 19 Nov), the language boards Code-1280-Mate, Code-640-MateLight, Agents-Mate-1280 (transcript, composer, session rows) and Components, and Device UX R5-iPad-11-list-shown (today's iPad layout). Today Code has a chat column on the right (⌘B or ⌃⌘S, resizable, at most half the window, stacked under the editor below 1100 pt) that opens straight into a chat with a session it guesses (the one bound to the worktree, else the newest open one); its header is the status icon, a session select of the worktree's sessions, Context ⌘I and + New chat. Wiki has no panel: to ask an agent about a page you leave for Agents and lose your place. Decided (do not change): the panel is one SDUI tree that the agents plugin renders, identical in Code and Wiki; opening the panel shows a session picker every time, not a chat; the suggested session is first, marked and focused, so ↩ takes it; then all other open sessions of the workspace (not only this worktree's); then a New session button; after the pick, the usual transcript and composer; the chat header has a way back to the picker. The plugin decides the suggestion and sends it with a reason, the client only draws it: 1) in Code with a review tab current, that review's opener ("opened this review") or else its Send recipient ("gets this review's comments"); 2) the session last picked in this panel for this context, the worktree in Code, the workspace in Wiki ("last used here"); 3) the newest open session ("newest"). In Code with a review current, New session starts a session that knows the review (base, head, worktree) and becomes its opener. The session sees what you look at: the file and selection in Code, the open review in Code, the open page in Wiki. Please put this round on page r1, at most 6 boards, 1280 Mate dark + 640 Mate light, iPad only where it differs. Show 2 or 3 directions, each with a one-line pitch, for: (1) the picker: rows (title, status, worktree or branch when it is not this one, age, needs-you), the suggestion mark and its reason line, New session (and its label when a review is current, e.g. "New session for this review"), the empty state (no open sessions), long lists (20+ sessions: filter field or show-more row), and keys (↩ takes the focused row, ↑↓ and j/k move, a key for New session; note ⌘N is already New in each section and a bare Esc is reserved for the app); (2) the chat header after the pick with the way back to the picker and how the context shows (file, review or wiki page, e.g. a chip near the composer); (3) the panel in Wiki: where it sits next to the margin column, its width, and its toggle key (in Wiki ⌘B is Toggle Sidebar for the wiki tree, so say which key toggles the chat there and whether Code and Wiki should share one key); (4) iPad (Companion renders the same SDUI): side panel or sheet in Wiki and in a review, or say it is out of scope for now.
