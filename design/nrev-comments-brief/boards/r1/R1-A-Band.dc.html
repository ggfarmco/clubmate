A · Band: each open comment is a tinted slab under its line

Every open comment line gets a background, padded with spaces from the code indent to the window edge, so the comment reads as one block that is plainly not code. Issues take the amber tint; every other type the raised grey.

1 Separation. A band from the start line's indent to the pane edge (raised; vt_warn for issues) and a heavier rule ▌ in the type tone. Stays below the line. No blank lines: the band edge is the separator.
2 Colour. Three tones: issue amber (band, rule, title), suggestion and question blue, note neutral (muted rule, fg title), praise teal. Only an issue's band is coloured.
3 Header. Icon and type in bold. No author or time. The keys hint keeps its wording but shows only on the comment whose range holds the cursor (here the note).
4 Resolved · drifted. Resolved drops the band: one grey italic line with the first words. Drifted keeps the band; the rule breaks (╏), the header says ⚠ code changed in amber, the sign turns ⚠.
5 The code line. Sign ✎ in the type tone, line number in the type tone, bold. No line highlight, so CursorLine and diff fills stay readable.
Blame. gitsigns blame moves to the right edge and drops the summary (You, 28 days ago). Without a band it is now the quieter of the two.
