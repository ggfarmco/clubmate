Workspace picker · round 2

Claude Design, 24 Nov. The user: switch to another Mac's last used workspace in 1 tap, not 2 (today: open the Mac's submenu, then pick). Three small directions inside direction A; each stays a system Menu, changes nothing with 1 Mac, adds no plugin field, costs S.

a · Last used under each Mac (designer's pick): keep every Other Macs row as it is; put that Mac's last used workspace right under it, one tap away. Nothing moves; +1 row per other Mac.

b · Recent: a Recent section on top with the last 3 workspaces you opened on other Macs, newest first. The Mac name goes into the subtitle (cut to 12), so only the first state fits and an offline row loses its state; rows reorder with use.

c · A section per Mac: every Mac gets a section like this Mac's: header = Mac name, its last used workspace first, then "All N workspaces" opens the rest. The Mac row people know today goes away.

"Last used" (a, c): per Mac, the workspace that was last current on this phone while you were on that Mac (a pick in the menu, a notification, an Inbox row, a deep link). Stored on the phone beside the saved tab stacks, keyed by the Mac's pairing ID; no sync; none yet or gone → that Mac's Home. Dashed outlines on the boards mark the new rows.

2 · "Last used", exactly (a and c)

  • Set when a workspace becomes current on this phone: a pick in the capsule menu or the submenu, a notification, an Inbox row, a deep link. Opening a submenu without picking sets nothing.
  • Key: the Mac's pairing ID; value: the workspace name (Home included). Kept beside the saved tab stacks, survives relaunch, removed with Forget this Mac. This phone only, no sync.
  • Shown for every Mac but the current one: the current Mac's workspace is the checked row in its own list.
  • Fallback: no entry, or the name is no longer in that Mac's workspace list → Home of that Mac.
  • Not used: the workspace last active on the Mac itself. It is the Mac's view, not this phone's, and would need a NEW plugin field; the user asked for where they were.
  • The shortcut is a Toggle that is never on: it is never the current workspace. The same workspace stays in that Mac's submenu.

4 · Why a

  • Does exactly what was asked. The last used workspace on each other Mac is 1 tap; everything else is where it is today, including the 2-tap path through the Mac row.
  • Nothing moves, nothing squeezes. Rows stay in Mac order (b reorders with use); the Mac name keeps its own row (b and c cut it harder); offline rows keep "as of 23:52 · {state}" (b loses the state).
  • Going back and forth is 1 tap each way. When you switch Mac, the Mac you left gets a shortcut to the workspace you just left.
  • Cost S, no plugin change. One phone-local value per Mac, one row per other Mac. iPad gets it for free: the capsule shows the same menu when the sidebar is hidden.
  • Trade-off we accept: +1 row per other Mac pushes this Mac's list down (2 rows with 3 Macs), and VoiceOver hears the Mac from the row above the shortcut, not from the shortcut.
