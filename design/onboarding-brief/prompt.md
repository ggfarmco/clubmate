Clubmate · Onboarding, round 1. Hi. This is a new canvas for one question: what a new user sees in the first minutes of Clubmate, and how the public GitHub repo looks. Clubmate opens to a wider public soon. The audience: people who already use Claude Code and want to run agents on a Mac. Page `today` has real screenshots of today's first run (board `Today`, each shot named in bold); page `language` has the language boards (`Principles`, `Tokens`, `Components`, `Patterns`, `C-Language`, `C-Components`, `C-Workspace`, `Mac-Settings-Remote`, `Agents-Mate-1280`). Draw on top of them.

1. Today (shots on `Today`). First start, no workspace: Welcome (`mac-firstrun`) dimmed under the editor sheet (`mac-editor-sheet`, "Choose your editor": Neovim default, VS Code with a licence + extensions step; esc keeps Neovim). That sheet is the only first-run step. Welcome (`mac-welcome-empty`, `mac-welcome-recents`): "Clubmate", two tiles Open folder… ⌘O and New terminal ⇧⌘N, the Home row (⇧⌘H), then Recent. When the first project opens in Code, Neovim asks a second question (`mac-nvim-import`): bring ~/.config/nvim into Clubmate, Import with an agent / Not now. Agents in a new project (`mac-project-agents`): "Start an agent session with + New", New session ⌘N. Home's empty Agents, Backlog, Wiki (`mac-home-*`) follow `design/features/home-workspace` § Empty Home. Nothing checks the environment before the first agent: the first session installs claude-agent-acp with npm (needs Node 22+, error "Node 22+ is required to run Claude"), Claude sign-in happens inside the session when Claude asks for it, git is needed for worktrees, checkpoints and the wiki. Phone: the Companion before pairing (`iphone-first`, dark + light) says "Pair a Mac: On your Mac, open Clubmate Settings → Devices → Pair Device…, then scan the code. Both devices need Tailscale." (a relay works when Tailscale can't). The Mac never offers pairing by itself; it lives only in Settings › Devices (`Mac-Settings-Remote`).

2. What the user wants. "New terminal" on Welcome is not needed now that Home exists: remove it or demote it (the key ⇧⌘N may stay). A short first run that gets a Claude Code user to a working agent fast, without a wizard they must click through. The editor sheet looked at again. Phone pairing offered at the right moment, not on first start by force. A public README and GitHub About that show what Clubmate is in one look.

3. Questions for you. Give 2–3 directions (A/B/C), each with a one-line pitch and your pick.
(1) Welcome: what it offers instead of "New terminal". Options we see: Open folder… alone as the one primary action; "Clone repo…"; Home as a big tile; a "Start an agent" entry. Your call; keep it keyboard first.
(2) First-run flow and order: environment check (Claude Code installed and signed in, Node 22+, git, macOS permissions such as notifications) → editor choice → first agent → phone pairing. Which steps exist, which are skippable, which run only when something fails. Sheet, a Welcome panel, or inline in Home / the project? Where does the nvim config import question go? Show the "all good" state (one line or nothing) and one failing state (e.g. Node missing, not signed in) with its fix action.
(3) First agent: a short tour or empty-state hints. What the empty Agents says on first run, a first suggested prompt, how "Needs you", worktrees and the phone get introduced (or not). At most 3 hints; no coach marks that block the screen.
(4) Companion pairing: when to offer it (after the first agent finishes a turn? when the Mac is about to sleep? in the first-run checklist as optional?) and how (a quiet row, a notification, a card in Home). Also the phone's own first screen: does it change?
(5) GitHub repo, no landing page: README structure (hero image, one-sentence what it is, install, main features with small shots, requirements, links), the hero image and the social preview 1280×640 built from real app screens in the design language (Mate dark, monospaced), the GitHub About line (≤ 120 chars) and 5–10 topics. Facts for the README: macOS 27+, signed and notarized DMG from GitHub Releases, auto-update with Sparkle; needs Node 22+, a Claude Code login, git; Companion on iPhone/iPad (iOS 27) over Tailscale or a relay. Main features: Agents (Claude Code over ACP, a worktree per agent, git checkpoints each turn, Needs you), agent graphs (coder → reviewer loops), land gates (a reviewer graph approves before a squash land), Companion (watch, answer, prompt from the phone; no backend), Backlog shared with agents, Wiki that agents write, Cron and Triggers, Voice (⌥Space), Neovim built in or VS Code, an agent browser, keep awake + notifications. Pick the 4 that lead.

4. Constraints. Keep the design language (`Principles`, `Patterns`, `Components`; colour roles, not hex; the Mac font is the terminal font, monospaced; compact, keyboard first; sentence case in Welcome, sheets and palette; app menus keep Title Case). Empty states are the `empty` node (icon, title, one text, one action button); settings rows are `SDUISettingsRows`; badges only for attention. What a state means (env OK, needs sign-in, paired) is decided once in a Go plugin and sent to clients as a field; the Mac and the phone render it. A first-run step that the user skips never comes back as a modal; it may stay as a quiet row. No new screen on the phone unless it is needed.

5. Deliverables. Put this round on page `r1`, at most 6 boards: 1280 Mate dark, 640 Mate light only where it differs, phone dark/light only where it differs. Suggested: Welcome (your directions side by side); first-run flow (the steps as small frames in order, with the failing state); first agent + hints; pairing offer on the Mac + phone first screen; README + hero + social preview 1280×640 + About/topics; a rules board with your picks, every text, and a handoff list with each change tagged (a) token/renderer (client SwiftUI), (b) new SDUI node or prop, (c) plugin content (words, order), (d) new plugin or core logic. Prefer (a) and (c).
